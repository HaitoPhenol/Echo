# 日记超级块运行时化：时间戳刷新修复、段框与段补齐

## 1. Summary

把目前只存在于**导出层**的「时间戳段 = 垂直超级块」分组逻辑下沉为编辑器**运行时派生模型**，并据此修复：

1. 删除末段时间戳后，上一段时间戳在下方已有正文时无法刷新时间；
2. 运行时无法判定块属于哪个段，导致待启用时间戳只能是一个 `bool`；
3. 段范围在 UI 上不可见；
4. 段结构被破坏（时间戳后没有正文块）时没有补齐。

本次**不改** **`.sy`** **格式、不改导出序列化、不引入嵌套模型**：分组仍由块列表位置派生，`.sy` 落盘仍是扁平结构，导出仍由 `SySerializer._rowSegments` 现算超级块。

## 2. Current State Analysis

### 2.1 时间戳待启用：单 bool 只能跟踪最后一个 stamp

[block\_editor\_controller.dart](file:///home/phenol/Documents/GitHub/Echo/echo/lib/src/diary/editor/block_editor_controller.dart#L74-L82)：

```dart
bool _stampPending = false;

```

[block\_editor\_controller.dart](file:///home/phenol/Documents/GitHub/Echo/echo/lib/src/diary/editor/block_editor_controller.dart#L204-L260)：

* `_initStampPending()`：只取**最后一个** stamp，且要求其段内为空；

* `_refreshStampPending()`：只处理最后一个 stamp；段内已有内容时直接 `return`，
  且 `if (!_stampPending) return;` 依赖单 bool 的上一次状态；

* `_restampStamp()`：改写 stamp 文本为 `formatDiaryStamp(now)`。

问题场景：`[A(空段), B(stamp, 有正文)]` 删除 B 后，A 的段变成有正文；
A 在挂载时因为没有段内内容而**未被记录为待启用**（它不是最后一个 stamp），
因此删除后没有机会重打点 → 用户看到的「上一时间戳不刷新」。

### 2.2 分组只在导出时派生

[sy\_serializer.dart](file:///home/phenol/Documents/GitHub/Echo/echo/lib/src/diary/sy/sy_serializer.dart#L200-L250)
的 `_rowSegments` / `_segmentSuperBlock` 在导出时按「stamp 开始、下一个 stamp 前结束」
切段。编辑器内的 `_segmentEmpty` 也重复实现了同一套扫描逻辑。

### 2.3 段结构没有守卫

* `attach()` 只保证文档至少一个块；

* `deleteBlock()` / `moveBlockAt()` / 退格合并 / 回车拆分后，都可能出现
  「stamp 后没有正文块」（stamp 位于文档末尾，或两个 stamp 相邻）；

* 目前没有统一的段补齐逻辑。

## 3. Proposed Changes

### 3.1 `lib/src/diary/sy/diary_model.dart`：新增派生分组唯一事实来源

在 `DiaryStamp` 内新增：

```dart
/// 一个块在时间戳段（运行时超级块）中的位置。
///
/// 段 = 一个时间戳块 + 其后到下一个时间戳之前的全部块；
/// 首个时间戳之前的块（如概述段）不属于任何段。
class StampSegmentEdge {
  const StampSegmentEdge({
    required this.inSegment,
    required this.isFirst,
    required this.isLast,
  });

  static const StampSegmentEdge outside = StampSegmentEdge(
    inSegment: false,
    isFirst: false,
    isLast: false,
  );

  final bool inSegment;
  final bool isFirst;
  final bool isLast;
}

/// 逐块计算段边界：与导出 `_rowSegments` 同一套位置语义。
///
/// 不在段内的块（首个时间戳之前）全部返回 [StampSegmentEdge.outside]。
static List<StampSegmentEdge> edgesOf(List<DiaryBlock> blocks) {
  final edges = List<StampSegmentEdge>.filled(
    blocks.length,
    StampSegmentEdge.outside,
    growable: false,
  );
  var start = -1;
  for (var i = 0; i <= blocks.length; i++) {
    final isBoundary = i == blocks.length || blocks[i].isStamp;
    if (!isBoundary) continue;
    if (start >= 0) {
      for (var j = start; j < i; j++) {
        edges[j] = StampSegmentEdge(
          inSegment: true,
          isFirst: j == start,
          isLast: j == i - 1,
        );
      }
      start = -1;
    }
    if (i < blocks.length) start = i;
  }
  return edges;
}
```

保留现有 `lastIndex / segmentHasContent / isPending`，供落盘清洗与旧调用方使用。

### 3.2 `lib/src/diary/editor/block_editor_controller.dart`

#### 3.2.1 待启用状态：单 bool → stamp id 集合

替换 `_stampPending`：

```dart
/// 待启用 = 该 stamp 的段内目前没有任何用户内容（时间戳时间尚未锚定）。
///
/// 集合按 stamp id 记录，支持同时存在多个待启用时间戳；`pendingStamp`
/// 保留原语义，只回答「最后一个 stamp 是否待启用」。
final Set<String> _pendingStampIds = <String>{};

bool get pendingStamp {
  final index = _lastStampIndex();
  return index >= 0 && _pendingStampIds.contains(_states[index].block.id);
}

/// 全部待启用 stamp id（测试/诊断用）。
Set<String> get pendingStampIds => Set<String>.unmodifiable(_pendingStampIds);
```

`_initStampPending()`（挂载/撤销恢复后调用，**不重打点**）：

```dart
void _initStampPending() {
  _pendingStampIds.clear();
  for (var i = 0; i < _states.length; i++) {
    if (_states[i].block.isStamp && _segmentEmpty(i)) {
      _pendingStampIds.add(_states[i].block.id);
    }
  }
}
```

要点：所有「段内为空」的 stamp 都进入待启用集合（不只最后一个）。
这正是修复删除末段后上一段无法刷新问题的关键：`A(空段)` 在挂载时即为待启用。

`_refreshStampPending()` 改为全量校准（结构变化与文本变化都调用）：

```dart
void _reconcilePendingStamps() {
  final present = <String>{};
  for (var i = 0; i < _states.length; i++) {
    final state = _states[i];
    if (!state.block.isStamp) continue;
    final id = state.block.id;
    present.add(id);

    // 段内为空：保持/进入待启用，时间戳文本暂不改变。
    if (_segmentEmpty(i)) {
      _pendingStampIds.add(id);
      continue;
    }
    // 段内已有内容且此前待启用：此刻才把时间锚定为「动笔时间」。
    if (_pendingStampIds.remove(id)) {
      _restampStamp(i);
    }
  }
  // 已删除的 stamp 一并清理。
  _pendingStampIds.removeWhere((id) => !present.contains(id));
}
```

`_restampStamp()` 保持现有实现（写 `formatDiaryStamp(now)` + `updatedAt` + `notifyListeners`）。

语义边界：

* 段内一旦有内容，`_pendingStampIds` 移除该 id → 该时间戳从此冻结，
  后续输入/结构变化不会再次改写（已落盘历史时间不动）；

* 段内容被清空 → 下次校准重新加入待启用，再次输入时重打点（沿用 2026-10-19
  既有裁定与测试）；

* 锁定文档不会触达校准入口（所有结构/文本入口都有 `locked` 守卫）。

#### 3.2.2 段补齐：`_normalizeSegments()`

新增私有方法，保证「每个 stamp 后至少有一个非 stamp 块」：

```dart
/// 补齐每个时间戳段：stamp 位于末尾、或下一块仍是 stamp 时，插入一个空段落。
///
/// 只补正文，绝不凭空创建新 stamp；锁定文档不处理。
/// 返回 true 表示块列表发生变化（调用方负责 sync + 置脏）。
bool _normalizeSegments() {
  if (locked) return false;
  var changed = false;
  for (var i = 0; i < _states.length; i++) {
    if (!_states[i].block.isStamp) continue;
    final next = i + 1;
    if (next < _states.length && !_states[next].block.isStamp) continue;
    final block = DiaryBlock(id: _ids.next(), text: '', updatedAt: _now());
    final state = BlockState(block)
      ..lastValue = const TextEditingValue();
    state.controller.addListener(() => _onBlockText(state));
    _states.insert(next, state);
    changed = true;
    i = next;
  }
  return changed;
}
```

调用点（全部在已有结构变更之后、`_syncDocBlocks()` 之前）：

| 位置                       | 处理                                                                                                        |
| ------------------------ | --------------------------------------------------------------------------------------------------------- |
| `attach()`               | 建好 `_states` 后执行；返回 `bool changed`；changed 时 `_syncDocBlocks()` + `_markDirty()`；最后 `_initStampPending()` |
| `_splitByInsertion()`    | `_states.insertAll` 后补齐，再 sync / dirty / reconcile / notify                                               |
| `handleBackspace()` 两个分支 | 删除或合并后补齐                                                                                                  |
| `deleteBlock()`          | 删除后补齐；随后计算焦点                                                                                              |
| `moveBlockAt()`          | 搬移后补齐；并补上当前缺失的 `_reconcilePendingStamps()`                                                                |
| `_restoreSnapshot()`     | 重建 `_states` 后补齐 + `_syncDocBlocks()`，再 `_initStampPending()`（撤销恢复**不**触发重打点）                             |

`attach` 签名改为：

```dart
/// 载入文档；返回 true 表示挂载时补齐了段结构（调用方需立即落盘）。
bool attach(DiaryDocument document) { ... }
```

现有 `..attach(doc)` 级联调用不受返回值影响，测试无需改签名。

#### 3.2.3 文本入口

* `_onBlockText` 的两条提前返回路径（组词中、无换行）：
  `_refreshStampPending()` → `_reconcilePendingStamps()`；

* `_splitByInsertion` 末尾同样替换；

* 结构路径按上表补齐后再校准。

## 5. Assumptions & Decisions

1. **派生分组，不落盘**：段边界由 `DiaryStamp.edgesOf` 每次从块位置派生；
   `.sy` 仍是扁平编码，导出层 `SySerializer` 完全不动。
2. **待启用 = 段内当前为空**：挂载/恢复时对**所有**空段 stamp 建立待启用；
   段一旦有内容即移出并冻结时间；内容清空后重新待启用并在下次输入时重打点。
   这既满足「只刷新未落盘时间戳」，也修复了中间空段在删除后无法刷新的情况。
3. **补齐只补正文**：`_normalizeSegments` 只插入空段落，不创建新 stamp；
   允许用户删光所有 stamp；锁定文档不补齐。
4. **补齐后的落盘**：`attach` 返回 changed，由编辑页立即落盘；其余结构操作
   已在 `_markDirty()` 链路内，走既有防抖保存。
5. **撤销恢复不重打点**：`_restoreSnapshot` 只重建待启用集合。
6. **段框样式**：`AppColors.tone1` 1px，逐块左右 + 首顶 + 末底，段内零间距；
   不加圆角（避免非均匀边框与圆角冲突），不做嵌套容器。
7. **临时工作政策**：按用户要求只改代码、不代运行；由用户自行运行
   `flutter analyze` / `flutter test` 与真机验证。测试文件同步更新以保证可编译。
