## 1. 原则

> 稳定级别标定（级别定义见 [governance.md](governance.md) 第 2 节，
> 级别调整须走 RCR）：
> **【铁律】** 1.1、1.2、1.3、1.4、1.5、1.6、1.8、1.12；
> **【约定】** 1.7、1.9、1.10、1.11、1.13、1.14；
> 新增规则必须自带级别标注；条文中的"参考做法"类表述属【参考】。

### 1.1 版本与提交纪律

- 版本号 `0.MINOR.PATCH+BUILD`（见 `echo/pubspec.yaml`）：
  - MINOR 在功能更新时 +1；PATCH 在 bug 修复时 +1，MINOR 增加时 PATCH 清零；
    首位 0 保持到正式发布，正式发布时升 1.0.0；
  - `+N`（Android versionCode）**永远只增不减**，即使版本名回退；
  - 每个版本节点打 git tag（如 `v0.5.0`）。
- 提交信息用 Conventional Commits：`feat:` 新功能 · `fix:` 修复 ·
  `refactor:` 重构 · `docs:` 文档 · `chore:` 杂项；标题简述，正文说明原因。
- 不主动 commit / push / 打 tag，除非用户明确要求；不 amend、不 force push。

### 1.2 文档与代码保持一致

- 每次新增或改动功能后，做文档对照审计：[architecture.md](architecture.md)、
  [glossary.md](glossary.md) 与源码逐句核对（术语、文件位置、数值、数量），
  发现过时描述立即修正。
- 注释解释"为什么"和适用条件，而不只是"做什么"。手段变更时注释必须跟着改，
  不允许注释描述一个已经不存在的实现。

### 1.3 单一事实来源与配置驱动

- 每类信息只有一个权威来源。例如"有哪些页面"只由导航配置描述，
  界面、指示器、搜索都从同一份配置读取，禁止各处各写一份。
- 新增同类内容优先走"加一条配置"，而不是改框架代码。
- 同一数值（几何尺寸、时长、热区等）只允许定义一次，视觉与命中共用同一来源；
  发现重复常量要收敛，不得再复制粘贴一份。

### 1.4 依赖方向（分层意图）

- 依赖只能向内：`pages` → `navigation` → `services` → `theme`。
  **services 不得依赖 navigation/pages 等 UI 层**。
- 可复用能力（搜索、触感、状态服务）面向抽象接口定义，UI 依赖抽象而非具体实现；
  换实现（如内存存储换持久化）时调用方零改动是设计目标。
- 文件按职责归位，不要把文件放得到处都是；优先编辑已有文件，不新建文件除非确有必要。

### 1.5 视觉规范

- 颜色集中在调色板（`theme/app_colors.dart`）统一管理，按"语义"或"视觉亮度层级"
  取色，**禁止在组件里散落裸十六进制值和临时透明度**；新增视觉元素时先在调色板找
  对应语义，没有合适的就先补具名常量再使用。调色板的阶数与取值可随设计演进，
  但"集中管理"不变。
- 同一交互反馈在各组件中保持一致（按压色、动画时长语言等），不逐组件各做一套。
- 动画中的连续 alpha（脉冲、呼吸、急闪）允许跨阶插值，但基色必须用具名常量，
  不写裸 `Colors.white`。

### 1.6 元素身份必须稳定

- 在 Stack/Row/Column 中以 `if`/`for` 条件插入子节点时，需要跨帧保持身份的
  常驻节点必须带稳定 Key。框架按类型 + 位置配对元素：无 key 节点插入中部会使
  后续兄弟元素整体错位、渲染对象销毁重建，动画因此静默失效（事故 1）。
- 判断标准：这个节点是否需要跨帧保持同一个渲染对象 / State？需要，就给稳定身份。

### 1.7 差异形态之间要解耦，不做"万能变形组件"

- 当一个组件要在两种差异很大的形态间形变（如静止导航条 ↔ 全宽搜索框），
  用两个解耦组件在切换帧交接（起始外观一致使切换不可察觉）。
  合成一个组件必然出现覆盖层层级错乱、收回途中内容穿帮（事故 3）。

### 1.8 几何的事实来源唯一，且视觉与命中一致

- 可点击区域必须与用户看到的位置对齐，且二者从同一份几何数据推导。
- 运行时测量（GlobalKey 等）与静态推算都只是手段。无论用哪种，都要保证冷启动
  首帧稳定、不出现重挂载 / 断言问题。若改用运行时测量，必须先验证低端机冷启动
  并说明相对当前方案的收益（事故 4）。

### 1.9 时间相关行为要可确定地测试

- 物理模拟、倒计时等时间驱动逻辑，其时间源应能在测试中被确定性推进
  （当前实现选用帧时间戳而非墙钟，正是为此）。
- 在帧外（普通事件回调）不要直接读取可能过期的帧时间戳作为计时基准；
  需要基准时惰性记录于生效后的第一个帧（事故 5）。
- 墙钟 Timer 与帧时钟是两条时间线（App 后台、测试 pump 时行为不同）。
  同一状态机内混用必须想清每条线的语义；新增延时先判断它属于"动画 / 物理"
  还是"真实世界等待"，再选时间源。

### 1.10 动画性能原则

- 逐帧动画期间消除重布局：动画值只驱动变换 / 透明度 / 绘制，避免每帧改变约束。
  复杂内容固定尺寸放置、超出部分裁剪，需要隔离重绘时用 RepaintBoundary（事故 6）。
- 循环光效必须有逐帧重建的订阅（如 AnimatedBuilder），不能只在首帧取一次动画值，
  否则会"冻结"（事故 7）。
- 多个 AnimationController 并存于一个 State 时用 TickerProviderStateMixin。
- `didUpdateWidget` 中比较新旧状态时，不要读同一个可变对象的现值（新旧 widget
  拿到的都是现值，永远相等）；由父级 build 时把值捕获为不可变字段传入。
- 自适应内容不要用会改变自身尺寸行为的对齐方式（Container 加 alignment 在有限
  宽度下会撑满，事故 2）；需要按内容自适应并居中时用 `Center(widthFactor: 1)`。
- **描边与阴影画在裁剪层之外**：`Border` 的线跨盒缘（一半在盒外），
  放在 ClipRRect 内会被裁掉外侧半条、整圈变细；把"颜色+边框"合成的 DecoratedBox
  放在裁剪层外，ClipRRect 只裁内容，阴影同理（事故 11）。
- **动画中的圆角要显式夹取**：不要传 999 一类超大名义半径——渲染器横纵独立夹取
  （rx 夹宽/2、ry 夹高/2），形变过程中会产生椭圆角、端部像矩形遮罩。
  每帧按当前外框宽显式 `r.clamp(0, frameWidth / 2 - inset)`，保证两端始终半圆
  （事故 11）。
- **被前景遮挡的元素优先用物理遮挡，不要写位置显隐逻辑**：例如锚点始终全部挂载、
  画在不透明滑块下层，当前页段被物理盖住、拖动时自然滑入滑出。
  按位置阈值（如 <0.5）挂载/卸载会在临界点元素恰在前景边缘时突然弹出露馅
  （事故 13）。
- 验证动画是否真播放：读渲染对象身份（跨帧必须不变）与中间尺寸（应插值而非
  一步到位）；真机用 `dumpsys gfxinfo <包名>` 看 Janky frames / Missed Vsync。

### 1.11 行为必须有反馈

- 不允许出现"按了没反应"的控件：功能未实现时给明确占位反馈，
  触感、视觉、语义至少占其一。
- 非关键能力（如触感）失败时静默降级，不得打断交互主流程。

### 1.12 手感参数以真机验收为准

- 物理曲线、动画时长、热区等手感参数属于调参结论，改动前后必须真机对比
  （构建安装 → 实际手势操作 → 录屏 / 截图比对），模拟器与单元测试不能替代。
- 参数集中、具名、注明取值依据与适用条件（如"按 N 页场景压低"）。
  适用条件变化（页面数量、设备形态）时整体重新评估，不把调参注释当永久真理。
- 真机帧率以连续操作时 `dumpsys gfxinfo <包名>` 的 Janky / Missed Vsync
  帧数为准（部分 MIUI 版本 Total frames 显示 0 是系统怪癖，不代表没跑帧）；
  屏幕录制本身增加负载，录屏时测到的是最差工况。

### 1.13 最小依赖与工具变更

- 依赖与工具链服务于需求，不为"先进"而引入：新增三方依赖 / 框架前，
  先说明现有手段为什么不够、迁移成本与替代方案。
- 反过来，当现有手段确实成为阻碍时可以更换——工具不是规定，
  "按需、审慎、可回退"才是。更换后更新 [current_state.md](current_state.md)。

### 1.14 命名与文件

- 文件名 `snake_case.dart`，类名 `UpperCamelCase`。
- 非通用配置不放仓库根目录。
- 公共 API 写文档注释，重点说明"为什么"。

## 2. 交付门禁（工具可换，门禁不变）【铁律】

无论以后是否引入 CI，每次交付前都必须满足（门禁项增减走 RCR）：

1. **静态分析零问题**（当前：`cd echo && flutter analyze`）。
2. **全部测试通过**（当前：`flutter test`）。
3. **手感相关改动完成真机回归**，基础手势全部过一遍：横滑、点圆点翻页、
   上甩及反悔、双击直达、长按搜索、多指边界。
4. **新行为补测试；修 bug 优先补能复现该 bug 的回归测试。**
5. **文档对照审计**：architecture.md / glossary.md 与改动逐句核对。

### 测试写法约定

- 时间相关逻辑遵循 1.9：物理 / 倒计时走帧时钟，用 `tester.pump(...)` 手动推进，
  **不能用 pumpAndSettle**（存在持续运行的 ticker 时会永不结束）。
- 测试坐标若依赖具体几何，从几何常量计算，不要散落魔数；几何调整时同步更新测试。
- 优先给纯逻辑（物理、状态服务、几何 / 手势判定）写不依赖 widget 树的单元测试，
  不要全部堆进 pump 整个 App 的集成用例。
- UI 文案在多处复用时，用精确 Finder（`findsNWidgets`、作用域 descendant）
  避免 `find.text` 歧义；交互形态变更（如 Dialog → Route）时先补路由注册再改断言。

## 3. 历史事故档案

记录"症状 → 根因 → 对应原则"。具体手段可能过时，但更换手段前必须确认
同类问题不会复发。

| # | 症状 | 根因 | 对应原则 |
|---|---|---|---|
| 1 | 搜索框开合动画静默失效 | Stack 中部条件插入无 key 节点，框架错位配对，渲染对象销毁重建，AnimatedSize 首帧即终态 | [1.6](#16-元素身份必须稳定) |
| 2 | 历史胶囊自适应长度消失 | Container 设 alignment 后在有限宽度下撑满可用宽度 | 1.10 |
| 3 | 搜索开合动画消失、收回时滑块/锚点穿帮 | 试图让同一组件同时承担静止导航条与变形搜索框两种形态 | [1.7](#17-差异形态之间要解耦不做万能变形组件) |
| 4 | 冷启动异常 / GlobalKey 重挂载断言 | 首帧高负载期运行时测量触发布局重挂载 | [1.8](#18-几何的事实来源唯一且视觉与命中一致) |
| 5 | fuse 倒计时瞬间烧完 | 帧外读取过期帧时间戳（首帧前为 0）作为烧蚀基准 | [1.9](#19-时间相关行为要可确定地测试) |
| 6 | 开合动画"低帧率慢速"观感 | 逐帧动画中改变 TextField/文本约束，每帧重布局 | [1.10](#110-动画性能原则) |
| 7 | 锚点呼吸/急闪光效冻结 | DecoratedBox 只在首帧取一次动画值，无逐帧订阅 | 1.10 |
| 8 | 停留/倒计时逻辑无法确定性测试 | 墙钟 Stopwatch 不随测试 pump 推进 | 1.9 |
| 9 | 快速扫过/双击跳转途经页面被误判已读 | 已读应基于"同页连续停留达阈值"，而非"经过即读" | 见下 |
| 10 | 搜索面板展开后自动关闭 | 失焦与重建链路问题（元素身份 + 焦点延时判断） | 1.6 / 1.9 |
| 11 | 搜索胶囊边框偏细；开合动画中端部出现椭圆角/矩形遮罩感 | 描边跨盒缘被 ClipRRect 裁掉外侧半条；999 名义圆角被渲染器横纵独立夹取 | 1.10 |
| 12 | 半透明滑块"视觉正确"却挡不住下层锚点 | 半透明色（0x83FFFFFF）不形成遮挡层；遮挡需求必须用不透明色（现用 0xFF838383，亮度与旧双层合成结果一致） | 1.10 |
| 13 | 拖动时锚点在滑块边缘突然弹出露馅 | 按位置阈值（<0.5）挂载/卸载锚点，临界点元素恰在前景边缘 | 1.10 |
| 14 | 滑块按压变色（变黑/加描边/统一近黑）连续几版被用户否定 | 视觉反馈语言要克制，按压态不是必须有颜色变化；产品拍板后删整条无用状态链路，别留僵尸字段 | 1.5 / 1.11 |

**事故 9 的产品规则**：在同一页连续停留 ≥700ms 才算查看；快速扫过、
按住圆点连翻、双击直达途经的中转页不算已读。实现上以独立监听器观察激活页变化、
每次变化重置计时（不复用会被静音的翻页回调）。手势 / 翻页机制变化时此判定需重新验证。
