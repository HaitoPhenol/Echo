## 一、功能全景

智能导航线是 Echo 的第一个完整功能模块，悬浮在屏幕底部，承担「在
少数几个核心页面之间移动」与「随时唤起搜索」两件事。当前已落地：

### 1. 四页导航轨道

- 4 个页面：控制台、聊天、日志、我（页面本体目前是极简占位页）。
- 底部显示为：**左圆点 + 圆角窄条（内含滑块与锚点）+ 右圆点**，
  整体占半屏宽，贴底居中。
- **端点圆点**：按下即向左右各翻一页；边界页保持不动。按下时
  圆点由 tone1（白 α.16）提亮到 tone2（白 α.42），200ms 后复位。
- **滑块**：位于窄条内的不透明灰色胶囊，指示当前页位置；拖动它
  可在页面间移动。**按下与拖动全程无任何外观变化**（经多轮试错
  后由用户拍板，详见第四节）。

### 2. 拟物的翻页手感（核心亮点）

横滑翻页不是线性映射，而是一套完整的小型物理模拟：

- **速度自适应增益**：慢拖时增益 0.25（约 216px 才翻过一页，便于
  精调），快甩时平滑提升到 0.60（一次甩动越过 2~3 页），增益曲线
  用 smoothstep 平滑过渡。
- **惯性滑动**：松手后若速度足够，进入指数摩擦滑行（每秒速度衰减
  到约 4.5%），撞边界或速度过低时转入吸附。
- **弹簧吸附**：以刚度 240、阻尼 26 的近临界阻尼弹簧精确落到目标
  页，到位有轻微回弹感。
- **橡胶带**：拖到首尾继续外拉时，越界部分压缩 70%、最多溢出
  0.35 页，松手弹回。
- **页内磁力曲线**：靠近整页时移动被压缩（粘滞、不容易离开当前
  页），两页中间被放大（自然滑落），且严格满足 f(0)=0、f(0.5)=0.5、
  f(1)=1，整数页位置绝不偏移。

### 3. 滚筒指示器

横滑开始时，导航条上方浮起一个「滚筒」：

- 顶部是**页名标签**（如「聊天」），切页时播放上翻隐入、下方翻出
  的翻转动画。
- 主体是一条横向页标轨道（当前用数字序号占位，填入页面图标后自动
  切换为图标），当前页对齐中央刻度，激活页白底弹动放大、中央刻度
  同步高亮脉冲。
- 轨道两端 16% 渐隐遮罩；落位 650ms 后整体下沉淡出。

### 4. 长按搜索

在胶囊上长按约 0.45s，胶囊展开成全宽搜索框：

- **开合动画（Morph）**：半屏胶囊与全宽搜索框之间做宽度（380ms）、
  高度（320ms）、形状（圆角与底色，180ms）的联动形变；展开瞬间
  用一帧外观完全一致的「替身 pill」无缝替换真实导航条，用户察觉
  不到切换。
- **倒计时烧蚀边框（Fuse）**：展开后先有 0.65s 宽限，随后边框在
  2s 内烧完，烧完自动收起；一旦输入框获得焦点，倒计时取消。
- **搜索建议区**：无输入时显示最近搜索历史（chips，交错入场动画）；
  有关键词时显示实时结果，点击结果直接跳转到对应页面，形成
  「输入页名 → 得到结果 → 跳转」的真实闭环。

### 5. 上甩快捷操作弧

在胶囊上竖直上甩，沿弧线弹出三个圆形快捷操作项；手指横移切换选中，
松手触发并在选中项处播放涟漪，随后弧收起。图标与行为目前为占位。

### 6. 锚点状态（通知预留接口）

窄条内每个页面对应一个锚点，除常态外支持两级状态：

- **通知**（绿色呼吸，如聊天新消息）：页面被查看后自动已读；
- **异常**（红色闪烁，如日志报错）：必须显式处理完成才恢复。

各业务模块只需调用服务的上报接口，锚点自动响应，不依赖导航 UI。

## 三、代码特色与设计决策

### 1. 物理层与显示层严格分离

控制器内部的 `position` **始终是线性物理位置**，橡胶带、磁力曲线
等所有"手感加工"只在 `displayPosition` 这一层计算。滑块、滚筒页标、
中央刻度全部消费同一份显示位置，因此各处节奏天然一致；而物理模拟
本身保持简单，稳定、可测试。

### 2. 用「物理遮挡」代替显隐判断

锚点（4 个页面小点）**始终全部挂载**，结构为
`Stack(children: [锚点层, 滑块])`——不透明滑块在上层直接盖住当前页
段，拖动时锚点从滑块边缘自然滑入滑出。

早期按距离阈值显隐锚点，临界点会出现锚点在滑块边缘弹出/消失的
穿帮；物理遮挡彻底消除了判断逻辑，也没有任何临界帧问题。

### 3. 组件解耦 + 接口先行（贯彻项目偏好）

- **数据全靠注入**：SearchCapsule 不持有任何业务状态，控制器、
  文本、历史、结果、回调全部由父级注入，自身只负责外观。
- **搜索可扩展**：定义 `SearchProvider` 接口，接入联系人、文件等
  新数据源时只需新增实现并注册，界面零改动。
- **历史可替换**：`SearchHistoryStore` 抽象与内存实现分离，将来
  换持久化存储只替换实现。
- **通知可扩展**：`NavBadgeService` 抽象 + InheritedNotifier 下发，
  消息、日志模块只依赖接口上报；换持久化实现不影响调用方。
- **配置单一来源**：页面的 id / 名称 / 图标 / 构建器集中在
  `NavDestination`，导航屏、滚筒、搜索三方共读一份，新增页面只需
  在列表加一项。

### 4. 手势与视图解耦

屏幕根部用一个 `Listener` 统一接管原始指针事件，自行做横滑/上甩的
方向锁定后再分派，子组件完全不识别手势（圆点、滑块都是"纯展示 +
父级驱动"）。这避免了多个手势竞技场互相抢手势，也让热区可以由
几何常量直接计算，不依赖 GlobalKey 实时取矩形。

### 5. 为逐帧动画做的性能设计

- Morph 动画期间，文本等复杂内容放在**固定为目标尺寸**的 Positioned
  层里只动 opacity，约束逐帧不变、布局命中缓存，避免重布局拖慢帧率。
- pill 整体外包 `RepaintBoundary`，开合重绘不波及页面其他区域。
- 物理 Ticker **按需启停**：静止且无倒计时时停止帧回调，节省电量。
- 形状层尽量使用无子女的轻量色块，减少逐帧构建成本。

### 6. 几何细节的严谨处理

- 圆角名义半径 999，但渲染器会横纵独立夹取导致直边，因此每帧
  显式 `clamp(0, frameWidth/2 - inset)`，保证任何尺寸下都是正确的
  完整半圆/圆角。
- Border 跨盒缘易被 ClipRRect 裁掉，颜色盒与边框盒放在裁剪层之外。
- 滑块颜色刻意选用**真不透明**的 `0xFF838383`（其视觉灰度恰好等于
  旧「tone1 底 + tone2 滑块」两层半透明色的合成结果），而不是外观
  相同的半透明白——后者挡不住下层锚点。

### 7. 按压反馈：克制即正确

本模块在"按下后长什么样"上经历了完整一轮试错：滑块按下曾做变黑、
做描边，v0.4.5 又把滑块与圆点的按压色统一为近黑——用户先后全部
否掉。最终结论：

- **滑块按下无任何外观变化**，常态灰保持不动；
- **圆点按下仅小幅提亮**（tone1 → tone2），不变黑；
- 不为没有视觉变化的按压态在 State 中保留字段（v0.4.9 顺手删除了
  仅服务该视觉的 `pressed` 参数链路与 `_capsulePressed` 字段）。

反馈不必全组件强求一致，按每个元素自身的需要给。

## 四、经验总结（可复用的教训）

1. **半透明"看起来一样"不等于"能遮挡"**：物理遮挡必须用真不透明
   色；0x83FFFFFF 与 0xFF838383 同貌，但像素采样下前者挡不住锚点。
2. **凡是涉及临界阈值的显隐，都值得怀疑**：条件翻转的那一帧往往
   穿帮。能用层级遮挡、透明度连续变化解决的，不要用离散显隐。
3. **手感加工放在显示层**：物理模型保持线性简单，非线性曲线集中
   在一个出口函数里，既稳定又便于多消费者共享。
4. **动画冻结先查重建链路**：动画驱动的绘制必须经 AnimatedBuilder/
   Listener 逐帧重建；只在 build 里读一次 `animation.value` 会让画面
   停住，直到别的事件顺带触发重建。
5. **逐帧动画的性能瓶颈常在布局而非绘制**：固定约束 + 只动 opacity/
   transform + RepaintBoundary，是本项目验证有效的组合。
6. **名义大圆角要每帧按真实宽高 clamp**，不能信任渲染器的自动夹取。
7. **时间相关逻辑用帧时间戳而非 Stopwatch**：控制器内统一以
   `currentFrameTimeStamp` 为时钟，真机准确、测试中可随 `pump` 确定
   性推进。
8. **一个 State 字段只在有消费者时才存在**：视觉方案被否后，连同
   只服务它的状态、参数、setState 一起删除，避免死代码长期残留。
9. **多动画控制器共存时用 TickerProviderStateMixin**；`didUpdateWidget`
   中不要读同一个可变 Notifier；Stack 中常驻节点条件插入要带稳定
   ValueKey。
10. **真机验证以连续开合的 gfxinfo Janky/Missed 帧数为准**（本机
    MIUI 下 Total frames 显示 0 是系统怪癖）；屏幕录制本身有负载，
    测到的是最差工况。
